# Principles
1. 팝업보다 인라인: 핵심 입력·선택·다음 단계는 페이지 인라인/전환(스텝)으로. 모달은 되돌릴 수 없는 짧은 확인이나 아주 짧은 보조 입력에만 쓴다.
2. 모든 클릭 요소는 버튼 콘텐츠 중앙정렬 5종 세트를 적용한다: inline-flex; align-items:center; justify-content:center; line-height:1; vertical-align:middle.
3. UI에는 시스템이 실제로 아는 것만 표시한다. AI/시스템은 성공/실패만 보여주고 신뢰도·추정원인·자동 품질판정(과검출/누락)은 금지(사람·QA 몫).
4. 정보 흐름: 조작 컨트롤(스코프/옵션)은 영향 필드 뒤에, 설명·잠금·경고 안내는 영향 필드 앞/상단에 둔다.
5. 본문 16px·레이블 14px 이상. Alert/Info 박스에 좌측 컬러 띠(border-left) 금지 — 배경색+아이콘만으로 구분.
6. 표기는 HIAI(전부 대문자). HiAI/Hiai/hiai 금지.
7. 신규 HIAI 목업에는 목업 내비게이터(까망이)를 기본 포함한다 — 다크 플로팅, 드래그·접기·케이스 선택기·파일 간 ?param 점프.
8. OCR 상태 라벨·색은 OCR 상태 사전 규칙을 따른다(완료 초록/진행중 파랑/확인필요 주황/정확도낮음·인식실패 빨강/미진행 주황). CSS 변경 후 ?v= 갱신.
9. 선택지를 나란히 비교시키는 화면(유형·방식 선택 등)은 카드마다 같은 축·같은 문장 구조로 쓴다. 한쪽은 속도, 다른 쪽은 정확도처럼 축이 어긋나면 차이가 읽히지 않는다.
10. 배포 전 점검: 모든 버튼이 실제로 동작하는지(빈 핸들러 금지), 같은 기능의 UI가 두 벌 존재하지 않는지, 화면 문구가 확정 정책과 어긋나지 않는지 확인한다. 죽은 마크업·함수는 남기지 말고 제거한다.
11. HTML 일괄 수정 시 정규식이 태그 경계를 넘지 않게 한다(<button[^>]*> 처럼 '>'를 넘지 않는 패턴). 여러 곳을 한 번에 바꾸기 전 파일을 백업하고, 수정 후 레이아웃 컨테이너가 오염되지 않았는지 확인한다.
12. 화면·탭·스텝마다 고유 URL 해시를 부여하고 양방향 라우팅(화면 전환 시 해시 쓰기 + 해시 진입 시 화면 복원 + hashchange 리스너)을 구현한다. 실제 서비스처럼 링크 공유·새로고침이 되어야 한다.
