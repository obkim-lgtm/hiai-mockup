## 문서 작성 원칙 (이 기능의 PRD에서 배운 것)
- PRD는 **동작·상태·규칙·선택지**만 정의한다. 크기·색·형태·위치·문구 전문·확인 UI 유형(확인창/인라인 띠)은 디자인 소관 → 피그마·인벤토리에 둔다. QA는 UI 모양을 보고 테스트하지 않는다.
- 규칙은 한 곳(공통 규칙)에만 쓰고 화면 장은 그곳을 참조한다. 같은 규칙을 두 번 쓰지 않는다.
- 해소·트리거 조건은 **1가지**로 정의한다(예: `확인 필요(!)` 해소 = 저장 성공). 조건이 둘 이상이면 QA 케이스가 곱으로 는다.
- 이미 개발된 규칙이라도 QA가 모르면 **"이미 개발됨 — QA 참고"** 섹션으로 남긴다(§5 기본 설계 수정 정책).
- 이전 버전은 페이지 하단 `## 이전 문서` 토글로 보존. 새 버전은 맨 위에, 수정 사항 요약은 토글로.

## 핵심 규칙 (v2.1)
- **선택 기능.** 1단계(문항 확정) 저장 후 2·3단계는 순서 무관, 하나만 해도 적용.
- **저장 모델:** 모든 입력은 초안. 저장 = 전 단계 초안을 한 번에 저장본으로(단계별 부분 저장 없음). 채점은 저장본만 읽음. 초안은 모달 닫을 때 서버 1회 저장(새로고침·탭 닫기 유실). 단계 이동 시 확인 없음.
- **저장 조건:** 문항 1개 이상 + 지시문 빈 문항 없음(번호는 자유 텍스트, 중복·비움 허용). 활동지 파일은 업로드 즉시 보관돼 초안·저장본과 무관. `[저장]`은 변경 또는 `!`가 있을 때만 활성. `[저장 후 다음으로]`·`[저장 후 닫기]`는 항상 활성.
- **①②③ 채움 기준(저장본):** ① 문항 1개 이상 / ② 연결 1개 이상 / ③ 답안 또는 가이드 있는 문항 1개 이상.
- **카드 버튼 라우팅:** ① 비면 1단계 / ② 비면 2단계 / 그 외 3단계. 단 `!`가 있으면 가장 앞의 `!` 단계로(10-07 줄리 확정). 미연결 경고는 라우팅을 바꾸지 않음.
- **진입점 2곳:** 목록 카드 `[정교한 설계]` 버튼 / 기본 설계 **최초 완료 저장 직후** '빈 활동지가 있나요?' 1회(수정 저장 미표시). 설계 상세에는 진입점·정교한 설계 정보 없음. `임시 저장` 설계는 진입 불가.
- **2·3단계 잠금:** ① 비어 있을 때(저장본에 문항 없음). 초기화 뒤도 같음.
- **2단계:** 연결 이력(AI 실행 또는 직접 연결 진입)이 없을 때만 선택 화면(AI 연결 / 직접 연결), 그 뒤 재진입은 바로 연결 화면, 초기화 뒤 다시 선택 화면. 자동 실행 없음. 실패 시 전체 미연결 + 재시도, 저장·진행 막지 않음, 재진입 자동 재실행 없음. 경고 상시(미연결 문항 = 채점 제외 / 미연결 기준 = 기준명 경고 / 전체 미연결 = 기존 방식 채점). 기본 설계 요약의 연결 정보는 1단계 최초 저장 후부터.
- **채점 반영:** 연결이 하나라도 있으면 미연결 문항·기준은 AI 채점 제외. 하나도 없으면 정교한 설계 미사용 = 기존 방식(활동지·답안·채점기준 통째로) 채점, ② 비어 있음.
- **확인 필요(!):** ② = 기본 설계에서 채점요소 삭제·추가 후 저장 / ③ = 답안·가이드 있는 문항의 지시문 수정 후 저장. 해소 = 정교한 설계 저장 성공 1가지(초기화도 해소). 화면 안 안내는 조건 아님.
- **확인이 필요한 행동 7종(C1~C7):** C1 초기화(활동지 삭제 통합) / C2 연결 0개로 모달 닫는 저장 / C3 미저장 닫기 / C4 AI 다시 연결(연결 있을 때) / C5 활동지 변경·문항 다시 인식(잃을 내용 있을 때) / C6 문항 삭제 / C7 AI 실행 중 닫기(올립 추가). C4·C5는 잃을 내용 없으면 확인 없이 실행. '이동 전 저장' 확인 없음.
- **데이터 연쇄:** 채점요소 수정·급간 추가 = 그대로 / 채점요소 삭제 = 그 연결만 삭제 / 채점요소 추가 = 미연결 추가 / 문항 삭제 = 그 문항의 연결·답안 삭제 / 활동지 변경·다시 인식·초기화 = 연결·답안 초기화 / 인식·채점 결과는 정교한 설계 쪽 행동으로 바뀌지 않음.
- **과제물 인식과의 관계(10-07 맥 확인):** 문항을 저장한 평가는 과제물 인식도 그 문항 기준으로 학생 답안을 나눔. 인식 후 문항 추가 → 빈칸 추가 / 삭제 → 그 문항 답안만 삭제 / 지시문 수정 → 그대로. 재인식 없음. 활동지 변경·다시 인식·초기화 뒤에도 이미 나뉜 학생 답안은 그대로(이번 배포). 새 문항과 맞추는 규칙·과제물 화면 안내는 후속 배포.
- **용어 구분:** '학생 답안'(과제물 인식 결과) vs '모범답안'(3단계 입력). '선생님 확인 필요'(채점 현황 학생 태그, 기존) vs '확인 필요(!)'(정교한 설계 단계 표시). '문항 인식'(1단계 활동지 AI)과 '과제물 인식'(학생 답안 OCR)도 항상 구분해 쓴다. 줄리 10-12 댓글로 혼동 확인.
- **AI 실행 중(문항 인식·AI 연결):** 저장 버튼 3종 비활성 + 단계 이동 불가. 닫기만 가능하고 닫기 시 C7(계속 기다리기 / 중단하고 닫기). 중단하면 실패했을 때와 같은 상태(첫 실행이면 1단계 문항 없음·2단계 전체 미연결 + 다시 시도 / 다시 인식·AI 다시 연결이면 기존 데이터 유지), 재진입 시 자동 재실행 없음.
- **활동지 변경 = 즉시 반영, 되돌리기 없음(10-12 빌 확인, 올립 결정 '현재 개발 구조 따름').** 재업로드는 기존 파일 삭제 후 업로드이고 문항은 활동지에 딸린 데이터라 저장본 문항·연결·모범답안도 그 자리에서 삭제됨. 초안 규칙의 유일한 예외(§3.2). 실패 시 새 파일 + 문항 없음 + 다시 시도/직접 추가. C5 확인창이 "되돌릴 수 없음"을 알리는 것으로 대신함. (같은 날 잠깐 적었던 "되돌리기 = 저장본 복원"은 철회.)
- **AI 다시 연결(C4) 실패·중단 = 기존 연결 유지:** 성공했을 때만 기존 연결(직접 고친 것 포함)을 새 결과로 교체. 새 결과가 올 때까지 기존 연결을 지우지 않는 구현이 전제 — 10-12 빌에게 확인 요청 중(줄리 댓글 계기). 개발이 어렵다고 하면 "실패 시 전체 미연결 + 다시 시도"로 §3.4·C4·C7·QA 4곳을 함께 고친다.
- **기본 설계 삭제 시** 정교한 설계(활동지·문항·연결·모범답안)도 함께 삭제.
- **기본 설계 수정 정책(이미 개발됨):** 잠금 없음. 고친 건 고친 대로, 지운 건 지운 채로, 시스템이 따로 알리지 않음. 학생 `확인 필요` 태그(채점 현황 기존 태그)는 **교사가 입력할 게 생겼을 때만** — 채점요소 추가(새 요소 채점 전) / 급간 삭제(그 급간을 골랐던 학생의 요소 점수가 빔). 채점요소 삭제는 그 요소 점수만 사라지고 총점만 바뀌며 태그 없음(채점 완료 유지). 채점 후 채점기준을 지웠거나 새로 넣었을 때만 점수 유지/삭제 선택창 1회. 제목·배점·세부기준만 수정 또는 급간만 추가 → 선택창 없음. (10-12 올립·줄리 구두 확인)
- **경계:** 평가자료실 보내기에 정교한 설계 미포함 / 복사해서 만들기는 저장본 전부 복사(①②③·`!` 동일, 초안·인식·채점 결과 제외) / 기본 설계 '빈 활동지가 있나요?'의 [나중에 할게요]는 현행 저장 후 화면 그대로 / 채점 실행 전 안전망 확인은 후속 배포.
- **백로그·비범위:** 채점기준 AI 검토(일정 부족, 별도 PRD) / 문항 순서 변경(이번 배포 미지원, 인식 결과 순서 그대로) / 단계 완료 토스트·사전 경고 삭제. PRD에 '미정'은 남기지 않는다 — 이번 배포 동작 + 후속 배포 항목으로 쓴다.

## v1.4 → v2.0 → v2.1 결정 이력
- v2.0(줄리, 10-06): 정교한 설계만 분리. 진입점 설계 상세 카드 삭제. 확인 UI 대부분 확인창으로. OCR 무관으로 회귀(오류). 기본 설계 수정 정책·안내 2종 삭제.
- v2.1(10-12): OCR 관계 복원(맥 확인) / 기본 설계 수정 정책 §5 복원(기개발, QA용) / 확인 9종→6종(활동지 삭제=초기화, 이동 전 저장 삭제) / `!` 해소 1가지 / ①②③ 저장본 정의 / 저장 조건 명시 / C2 트리거 = 모달 닫는 저장 전부 / 디자인 사양 전부 제거.
- 올립 확정: 띠/확인창 구분은 디자인 소관(PRD에서 제외). 채점기준 AI 검토는 백로그.
- 10-12 줄리 제안 '문항 추가·삭제 시 학생 답안 OCR 재실행' → **불채택**(올립). 사유: 학생 전원 재인식 비용, 교사가 과제물 화면에서 손본 인식 결과를 덮어씀(원칙 3 '시스템이 임의로 초기화하지 않음' 위배), 인식 뒤 문항을 지웠다 다시 넣는 빈도 낮음. 발생 시 안내는 '삭제 대신 지시문 수정'. '문항 변경 뒤 답안 다시 맞추기'는 §7 후속 배포에만 둠(재인식/매칭 중 선택은 실발생 확인 후).
- 10-12 C4 문구 모순 해소: "기존 연결을 모두 지우고 다시 연결"과 "실패 시 기존 연결 유지"가 한 셀에 같이 있어 줄리가 빌에게 구현 확인 요청 → 올립이 '유지' 방향으로 통일(교사가 맞춘 연결을 AI 실패로 잃지 않게). 개발 의견에 따라 되돌릴 수 있음(위 핵심 규칙 참조).

## 남은 확인
- 디자인(줄리): 인벤토리 §6(다이얼로그 4종 + 띠 5종)을 C1~C6 기준으로 갱신.
- 올립: 노션 PRD DB "부 버전 발행하기" 버튼.
- 빌: 활동지 변경으로 문항이 삭제될 때 이미 나뉜 학생 답안도 연쇄 삭제되는지(C6 규칙대로면 삭제 가능성). PRD는 "학생 답안·채점 결과 그대로"라 어긋나면 §3.3·§4.3·C5 수정.
- 빌: AI 다시 연결(2단계)·문항 다시 인식(1단계) 실패·중단 시 기존 데이터 유지(새 결과 올 때까지 안 지움) 구현 가능 여부. 활동지 변경은 이미 '유지 불가'로 확정됐고, 다시 인식(같은 파일 재추출)만 남음. 올립이 §3.4 스레드에 질문, §3.3 줄리 스레드는 그쪽으로 모음. 불가면 PRD §3.3·§3.4·C4·C5·C7·QA "실패 시 비움 + 다시 시도"로 수정.
