```
설계 상세(기본정보·성취기준·채점기준·점수계산·결시자) → 저장 = 설계 완료
   └ [빈 활동지가 있나요?]  ← 저장 직후 1회, 이미 올린 설계엔 안 물음

        └ 없어요 → 목록
```

- **되돌아가기 O / 건너뛰기 X.** 뒤 단계가 앞 단계 산출물을 참조한다(문항이 나뉘어야 연결·답안이 성립). 못 가는 단계도 눌리게 두고 왜 못 가는지 토스트로 말한다
- **중간 이탈 = 하던 데까지 남음.** ①만 저장하면 ②③은 빈 채로
- **저장은 머문다.** ①②의 `저장`은 그 자리에 남고, 나가는 건 `이전 단계`·`설계로 돌아가기`와 ③단 `저장하고 마치기`만

## ②단 = 문항 × 채점기준 매트릭스 (2026-09-01 결정)

맥이 **좌우 두 열 + 선 긋기**를 제안했으나 채택하지 않음.
- **선 매칭은 N:M에서 무너진다** — 문항 10 × 기준 10이면 선이 최대 100개, 교차하면 못 읽음
- 양쪽 열 독립 스크롤 시 좌표 어긋남 · 드래그 정확도 · 키보드 조작 불가

**다만 맥이 짚은 문제(전체 조망 안 됨)는 실재**했다. 기존 마스터-디테일은 문항마다 클릭해야 하고, 무엇보다 **다 봤는지 스스로도 모른다.** AI가 이미 연결해 두므로 이 화면의 주 과업은 **확인**이고, 확인 과업에 클릭이 드는 건 손해.

→ **매트릭스 채택.** 행=문항, 열=채점기준, 칸=체크.

- 머리 두 단: 위 `채점기준`(열 묶음) / 아래 번호. **번호는 범례와 같은 파란 원 배지** — 숫자만 두면 위를 뒤져 짝지어야 함
- 상태는 **별도 열**(`연결` 96px) — 문항 길이에 밀리지 않게. 칩 3종: 🔴 `미연결` / 🟠 `확인 필요`(채점기준 변경 후) / 🟢 `연결완료`. 기존 `.badge` 재사용
- 지시문은 **한 줄 말줄임** — 두 줄이면 행 높이가 제각각이라 훑기 어려움. 전문은 hover
- `table-layout:fixed` + **colgroup 필수** — 첫 행이 colspan이라 colgroup 없으면 열이 균등 분할돼 문항 열이 100px로 쪼그라듦
- AI 이유는 표 **아래로** 모음(칸마다 붙이면 표가 안 읽힘). 배경 하늘색 `#F3F9FF` + 테두리 `#D9EAFB`

**실측(최대 조건 기준 10 × 문항 10)**: 문항열 502px · 상태열 96px · 체크셀 48px · 가로 넘침 없음 · 행 높이 균일.

# 2026-09-01 (2) — 회의 반영 4건 + PRD V1.0

## 확정된 정책 (회의 답변)

| 물어본 것 | 올립 답변 |
|---|---|
| 어느 문항에도 연결 안 된 채점기준은? | **채점에서 제외**되고 진행 |
| 채점기준을 고치면 채점 결과는? | **저장할 때 초기화하겠냐고 묻는다** — 문구·배점·추가 무엇이든 하나라도 바뀌면 |
| 문항 연결을 바꿔도 초기화? | **아니오.** 해당 시점 이후 채점부터 적용된다고 안내 |
| 미사용 기준이 있으면 만점 표시는? | **바꿀 필요 없음** — 사용자 의도이므로 |
| 활동지·문항을 바꿔도 초기화? | **아니오.** 루브릭 영향이 아니라 다음 채점 실행부터 적용 |
| PRD 어디에? | 기존 H-2608에 **새 버전으로 위에**, 구버전은 접어 둠(올립이 접어 놓음) |
| 복사 기능 이름 | **`복사해서 만들기`** (`설계 추가` 버튼 메뉴) |
| 복사 시 활동지 파일은? | **원본까지 따라감** |

**핵심 규칙 한 줄** — 초기화를 묻는 건 **채점기준 변경 하나뿐**이다. 루브릭이 바뀌면 만점과 기준 자체가 달라져 이미 매긴 점수가 근거를 잃지만, 연결·문항은 "무엇을 보고 채점할지"라 매긴 점수를 무효로 만들지 않는다.

## 반영한 것

**① 매트릭스에서 빈 행·열을 드러냄** — 연결이 없는 행·열을 옅은 빨강 바탕으로. 어느 문항에도 안 붙은 기준은 범례에 칩. 단 **미연결 문항이 있으면 그 문항이 전체 기준으로 채점되어 이 기준도 쓰이므로** `채점 제외`(전부 연결됨)와 `연결된 문항 없음`(미연결 있음)을 갈라 쓴다. 색만 칠하지 않고 표 아래에 뜻과 조치를 함께 적었다.

**② stale 연쇄** — `S.staleLink`(채점기준·문항 변경) / `S.staleAnswer`(문항 변경). 단계 칩의 주황 점 · 단 상단 안내 · 목록 카드 요약이 같은 상태를 가리킨다. 해제는 그 단계를 열어 `다음`/`저장`. **막지 않는다** — 다시 안 해도 채점은 되니까.

**③ 채점 후 잠금 폐지** — 배점·삭제를 자유롭게 열고, 저장 시점에 초기화를 묻는다. `채점 결과 지우고 수정하기` 버튼은 쓰임이 사라져 제거.

**④ 대기·완료 안내** — 로딩에 무엇을(순환) + 왜를 함께. 단계를 마치면 다음 화면 상단에 무엇이 좋아졌는지 1회. 되돌아가면 미표기.

**⑤ 채점기준 섹션 상단 안내** — 활동지를 올린 설계에서 채점기준을 고치면 그 자리에 안내 + ②단 이동 버튼. 고도화 카드의 같은 안내는 제거(한 화면에 두 번 말하지 않음).

## 문구 점검에서 잡은 것

- **미연결의 뜻이 사라져 있었다** — 매트릭스로 바꾸며 "연결하지 않은 문항은 채점기준 전체로 채점돼요"가 없어져, 색만 있고 무엇을 해야 할지 없는 상태였다. 되살림
- **잠금 안내가 금지만 말했다** — `문항을 바꿀 수 없어요`로 끝나 나갈 길이 없었다. `복사해서 만들기`로 새 설계를 만들라는 대안을 넣음
- **`앞 단계가 바뀌었어요`** — 교사는 '앞 단계'를 모른다 → `채점기준이나 문항이 바뀌었어요`
