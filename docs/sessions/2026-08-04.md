# 2026-08-04 · H-2608 정교한 평가 — 변경 규칙 재편 · 세트 교체 제거

## 무엇을 했나

빌·줄리 피드백에서 출발해 **변경 연쇄 정책이 케이스 나열로 불어나는 문제**를 원칙 하나로 접었고, 마지막에 "채점기준 세트 교체"라는 존재하지 않는 액션을 제품에서 걷어냈다.

## 정책 결정

### 1. 변경 규칙 = 참조 원칙 하나
케이스별 표(18행)를 규칙으로 두지 않고 **원칙에서 도출된 결과**로 격하.

> 뒷 것은 앞 것을 참조한다.
> 참조 대상 소멸 → 참조도 소멸. 내용만 변경 → 참조 유지, 적절성은 사람이 재확인.

- "수정"과 "삭제"의 경계 = 변경 폭이 아니라 **항목의 존속 여부**. 시스템은 변경 폭을 판단하지 않음
- 신규 케이스가 나와도 표를 늘리지 말고 원칙에 대입

### 2. 잠금은 두 축 — 섞지 않는다
| 축 | 시점 | 차단 대상 |
|---|---|---|
| 참조 | 과제물 **OCR 분석 실행** 후 (업로드만으론 안 잠금) | 참조를 끊는 변경 |
| 값 | **채점 실행** 후 | 배점 변경·세부기준 삭제 |

값 축은 이번에 새로 찾은 구멍. 배점 5→3점인데 교사 확정 4점이 남으면 모순인데, 재채점해도 교사 확정값은 보존되므로(기존 `needsRescoring` 정책) 영원히 안 풀린다.
**재채점은 반영 수단이지 잠금 판단 기준이 아니다** — v0.2가 이 둘을 섞어 서술했던 것을 정정.

### 3. 안내는 3종만
확인 필요(진행 바 표식) / 되돌릴 수 없음(확인 다이얼로그) / 잠김(비활성 + 단계 상단 **단일** 배너).
케이스마다 팝업·배너를 만들던 8종을 여기로 흡수. 항목마다 경고 붙이지 않음.

### 4. "채점기준 세트 교체" 제거
올립이 "그게 뭐야, 나 이해 못 함"이라고 한 시점에서 **제품에 없는 액션**임이 드러남. 실제로 존재하는 건 개별 추가·수정·삭제뿐.
- AI 채점기준 생성 = 기존 목록에 **추가** → 참조가 안 끊기므로 다이얼로그 없이 3단계 `확인 필요` 표식만
- 채점기준 **개별 삭제**에만 확인 다이얼로그 (문항 삭제와 대칭)
- 세트 교체 전용이던 3.5 예외(자동 재연결) 조항 통째로 소멸

### 5. 수동 재분석 버튼 안 만듦
케이스가 복잡해지니 "다시 분석" 버튼을 넣자는 흐름이 나왔으나 거절. ① 활동지 교체가 이미 그 일을 함 ② 교사 수정을 덮어씀 ③ 언제 눌러야 하는지 판단 근거를 유저가 못 가짐.
**UI로 복잡성을 덮지 말고 정책에서 줄인다.**

## 배운 것 (하네스에 남길 것)

- **`alert()` 금지** — 목업에서 한 줄 남아 있던 alert이 페이지 전체를 멈춰, 자동 검증이 30초 타임아웃 났고 원인 파악에 시간을 씀. 안내는 토스트로.
- **`applyLock`이 `onclick`을 덮어쓴다** — 잠금 해제 로직이 원래 핸들러명을 찾지 못해 영원히 안 풀리고 있었음. `dataset.prevOnclick`을 먼저 보도록 수정. **같은 잘못된 필터로 테스트해서 앞선 검증을 통과했었다** — 검증 코드가 대상 코드와 같은 가정을 공유하면 아무것도 검증하지 못한다.
- **한 줄짜리 함수는 `[\s\S]*?\n}\n` 정규식으로 못 지운다** — 다음 함수의 닫는 중괄호까지 달려가 뒤쪽 마크업을 삼킴. 중괄호를 세는 방식으로.
- **까망이 자동 동기화 vs 지연 렌더** — `setTimeout` 뒤에 상태가 도착하는 케이스는 `currentKey()`가 먼저 계산돼 하이라이트가 다른 버튼으로 튄다. 선택 키를 600ms 고정(`_mpForcedKey`)해 해결.
