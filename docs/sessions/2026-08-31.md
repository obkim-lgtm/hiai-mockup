## 왜 합쳤나
두 화면이 같은 문항을 두 번 그리고 있었다.

| | 빈 활동지 등록 | 채점 가이드·모범답안 |
|---|---|---|
| 카드 내용 | 문항 번호(입력) · 지시문(입력) · 순서이동/삭제 | 문항 번호(읽기) · 지시문(읽기) · 채점 가이드 · 모범답안 |

뒤엣것은 앞엣것이 끝나야만 열리는 종속 관계라, 설계 상세에서 늘 `빈 활동지를 먼저 올려 주세요`
**잠긴 버튼**으로만 보였다. 합치니 그 잠금 안내가 통째로 사라진다 — 잠금이 아니라 순서로 풀린다.

## 구성 — 한 화면, 두 단계 (C안)
```
활동지 올리기 → (자동) 문항 분석 → ① 문항 확정 → ② 문항별 모범답안·채점 가이드
```
- 설계 상세 섹션 `sec-worksheet` + `sec-answer` → **`sec-sheet` 하나**
- ①단 = 문항 목록 그대로(번호·지시문·순서이동·삭제·추가)
- ②단 = 문항 번호·지시문은 읽기, 그 아래 채점 가이드·모범답안
- 되돌아가도 적어 둔 답안은 남는다. 재진입 시 **답안이 하나라도 있으면 ②단으로 바로** 연다
  (답안이 있다는 건 문항이 이미 확정됐다는 뜻)

### A안(다 펼침)을 버린 이유 — 같은 세션에서 뒤집음
처음엔 문항 카드 하나에 번호·지시문·가이드·모범답안을 다 펼치는 A안으로 만들었다가 되돌렸다.

- 근거로 삼았던 "답안 쓰다 문항 오류를 발견하면 그 자리에서 고친다"가 **장점이 아니라 이미 손해가
  난 상황**이다. 답안을 다 쓴 뒤 문항이 틀린 걸 알면 `문항 다시 분석` → 답안이 전부 날아간다.
  문항 오류는 늦게 발견할수록 비싸므로, 순서를 세워 비싸지기 전에 발견하게 한다
- 두 일은 성격이 다르다 — 문항 확정은 실제 활동지와 대조하는 짧은 **검수**, 답안은 문항마다 생각해
  쓰는 **작성**. 검수하려면 문항 목록의 전체 형태가 한눈에 들어와야 하는데 입력칸이 끼면 묻힌다
- **"합치자"는 진입점을 하나로 만들고 잠긴 버튼을 없애자는 것**이지 두 과업을 동시에 펼치라는 게
  아니었다. 화면이 둘이면 잠긴 버튼이 상시 노출되지만, 한 화면 두 단계면 문은 하나고 단계는 흐름이다

## 버튼 (올립 확정)

| 자리 | 왼쪽 | 오른쪽 |
|---|---|---|
| 활동지 파일 카드 | — | `문항 다시 분석` · `파일 교체` · `삭제` |
| ①단 하단 | `설계로 돌아가기` | `저장` · **`모범답안·가이드 입력`**(primary) |
| ②단 하단 | `문항 수정` | `저장`(primary) |
| 설계 상세 요약 카드 | — | `빈 활동지 올리기` / `문항·모범답안 확인` |

- **①단에 `저장`이 있어야 한다** — 모범답안은 선택이라 문항만 확정하고 끝낼 길이 필요하다.
  `저장`+`모범답안 입력`을 한 버튼(`저장 후 모범답안 입력`)으로 합치는 안은 이 길이 사라져 접었다
- **버튼이 많다**는 문제는 `문항 다시 분석`을 하단에서 **파일 카드 옆으로** 옮겨 풀었다.
  올린 파일에 대한 행동이라 자리가 맞고, 하단엔 "이 화면을 끝내는 행동"만 남는다
- `모범답안 입력`(7자) → `모범답안·가이드 입력`(11자) — **채점 가이드만 쓰는 선생님도 있을 수
  있어서**(올립). `및`은 가운뎃점으로, `채점`은 빼서 길이를 줄였다. `답안·가이드`는 못 쓴다 —
  이 제품에서 `답안`은 학생 답안을 뜻한다
- `문항 고치기` → **`문항 수정`**

## 문구 (올립 확정)

- **②단 상단 설명은 두 문장** — `답이 정해진 문항은 모범답안을 넣어 주시면 채점이 정확해져요.
  비워 두어도 채점은 진행돼요.`
  - 주제형 통글은 굳이 안 써도 된다는 이야기는 **일부러 뺐다**. 반대편을 같이 말하면 강조가 죽는다
  - "문항 수정으로 돌아가도 내용은 남는다"도 뺐다 — 버튼이 바로 아래 있고, 사라지는 것은 경고하되
    남는 것은 굳이 말하지 않는다
- **"AI가 그대로 따릅니다"는 사실이 아니다**(올립). 세 군데를 `AI가 선생님의 채점기준을 더 잘
  이해해요` 계열로 고침 — ②단 채점 가이드 라벨 · 설계 상세 요약 설명 · 진단 화면 AI 제안 설명
- **②단 답안 개수 카운터(`문항 4개 중 0개 작성`) 제거** — 선택 항목인데 `0개`가 미완성으로 읽힌다

### 설계 상세 정리 — 같은 말을 두 번 하던 것들
| 자리 | 전 | 후 |
|---|---|---|
| 상시 설명 | "…올리지 않아도, 답안을 비워 두어도 저장할 수 있어요" | 삭제(그룹 머리가 이미 `(선택)`) |
| 상태 문장 | "활동지를 문항 4개로 나눴어요. 모범답안은…" | "모범답안은 아직 넣지 않았어요."(배지가 `문항 4개`) |
| 진단 버튼 | `AI 채점 적합성 진단` | `진단 시작`(바로 위 제목과 글자까지 같았음) |

각 줄이 한 가지씩만 말하게 됐다 — 배지=무엇이 몇 개, 설명=왜 하는지, 상태 문장=어디까지 했는지,
버튼=어디로 가는지.

## 같이 고친 것 — 답안이 문항을 따라가게
답안이 **문항 번호(`q.no`)에 묶여** 있었다. 두 화면일 땐 순서 편집과 답안 입력이 분리돼 드러나지
않았지만, 합치면 순서를 바꾸는 순간 답안이 엉뚱한 문항에 붙는다.
→ **답안·가이드를 문항 객체 자체(`q.answer` · `q.guide`)에 담는다.**

| 하는 일 | 답안·가이드는 |
|---|---|
| 문항 순서 바꾸기 | 그 문항에 붙어 같이 이동 |
| 문항 번호·지시문 수정 | 그대로 유지 |
| 문항 추가 | 빈 칸으로 새로 생김 |
| 문항 삭제 | 그 문항 것만 함께 사라짐 — 쓴 내용이 있으면 확인 문구에 명시 |
| 활동지 교체 · 문항 다시 분석 | 문항이 새로 나뉘므로 전부 사라짐 — 기존 경고 유지 |

## 검증
- 추출 JS `node --check` 통과 · 콘솔 에러 없음
- ①단: 업로드+문항 목록만, 답안 칸 0개 / ②단: 문항 4개 카드에 가이드·답안, 나머지 영역 숨김
- **②단 → 문항 수정 → 순서 변경 → ②단 재진입**: 라벨과 답안이 짝을 유지한 채 이동
- 문항 삭제: 그 문항 답안만 사라지고 나머지 유지, 확인 문구에 답안 언급 노출
- 문항 추가: 빈 답안 칸 생성 · 재진입 시 답안이 있으면 ②단으로 열림
- 버튼 노출: 활동지 전 = `설계로 돌아가기`만 / 문항 나뉜 뒤 = 저장·모범답안·가이드 입력 등장

### 잡은 버그 — 숨은 DOM이 답안을 밀어 넣음
`syncQuestionsFromDom`이 **숨겨진 ②단 DOM까지 읽어** 문항 객체에 되썼다. ①단에서 순서를 바꾸면
②단 DOM은 낡은 순서를 들고 있으므로, ②단으로 넘어가는 순간 답안이 한 칸씩 어긋났다.
답안은 `onQaInput`이 입력 즉시 문항 객체에 넣으므로 **②단 DOM을 다시 읽을 이유가 없다** — 그 경로를 끊었다.
