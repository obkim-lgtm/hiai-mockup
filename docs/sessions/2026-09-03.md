## ▶ 이어받기 — 여기가 현재

**어제 만든 시안1·2는 전제가 틀렸다.** 맥의 실제 출력은 채점기준별이 아니라
**전체 루브릭 하나에 등급 1개 + 코멘트 1개**다. 그래서 **시안3(배너 인라인)** 을 만들어 확정했다.

```json
{ "grade": "보완필요", "comment": "…문장으로 된 글 하나…" }
```
필드 두 개뿐. 등급은 점수가 아니라 **`우수` · `적절` · `보완필요` 3단계 말**.
지적이 둘 이상이면 코멘트 안에서 **문단으로 이어진다**. 어느 채점기준 얘긴지는 **글 안에 이름으로만**.

## 문구 — 세 단계 "왜 하는지"를 공식 사유로 교체

내가 쓰던 ①단 이득(`1-1, 1-2처럼 잘게 나뉜 문항도 경계가 확실해져요`)은 **폐기**.

| 단계 | 근거 원문 |
|---|---|
| ① 빈 활동지·문항 확정 | 문항 지시문을 미리 확정해 두면, 학생 제출물의 낙서·메모로 훼손된 지시문을 AI가 오독하는 것을 막는다 |
| ② 채점기준 연결 | 각 문항에 요구되는 채점기준만 적용해 평가한다 |
| ③ 모범답안·채점 가이드 | 선생님이 생각하는 "상" 수준을 AI가 파악해 추론이 불가능한 답안도 채점 / 채점 가이드로 채점 고려 사항을 반영 |

- ①은 두 안 중 **1안(낙서·메모 오독)** 채택 — 2안(*"답안에 더 집중"*)은 무엇이 좋아지는지가 흐리다.
  바꾸려면 `ADV_WHY[1]`·`ADV_GAIN[1]`·`ADV_LOAD.ws.why` 세 줄
- 업계어는 풀었다 — `훼손된 지시문 오독` → `낙서나 메모를 문제로 잘못 읽음`,
  `"상" 기준 수준` → `잘한 답안의 수준`, `추론 불가능한 답안` → `미루어 짐작하기 어려운 답안`
- **③단은 두 줄로 나눴다** — 모범답안과 채점 가이드는 서로 다른 이득이라 이어 붙이면 뒤엣것이 묻힌다.
  채점 가이드 쪽은 `적어 주세요`(부탁) → `적어 두면 … 선생님이 생각하시는 수준에 맞춰 채점해요`(이득)로

## 단계 성과는 토스트로

`#adv-gain`(초록 배너)를 **없애고 토스트**로 바꿨다(26-09-03 올립).
바로 아래 `adv-why`(파랑 상시 배너)와 겹쳐 **한 화면에 안내 박스가 둘**이었다.
게다가 ③단만 토스트고 ①②는 배너인 불일치도 있었다.

**성과는 지나가는 소식**(한 번 보면 끝), **왜 하는지는 머무는 안내**(고치는 내내 필요) — 토스트와 배너가 그 구분이다.
함께 걷어낸 것: `S.justFrom`, `.note-done` CSS.

## 까망이를 두 탭으로

케이스가 열여덟 개라 한 줄로 세우면 뭘 보는지 모른다.

| 채점기준 검토 (9) | 정확도 향상 (9) |
|---|---|
| 설계 목록 · 새 설계 · 설계 완료 | 저장 직후 분기 |
| 검토 결과 보완필요 · 적절 · 우수 | ① 활동지 올리기 전 · ① 문항 확정 |
| 검토 뒤 채점기준 고침 | ② 채점기준 연결 · ③ 모범답안 |
| (보류) 시안1 · 시안2 | ②까지 하고 나감 · 마친 뒤 상세 · 인식 후 · 채점 후 |

- **케이스가 바뀔 때만 탭이 따라간다**(`_mpLast`). 매번 따라가면 탭을 눌러도 제자리로 튄다
- **배너 상태가 바뀌면 까망이도 따라 움직인다**(`rvSyncCase`) — 검토 완료 → `rv-band`,
  고친 뒤 → `rv-stale`. 도는 중엔 손대지 않는다(5초 뒤 어차피 바뀌므로)

## URL

| 주소 | 뜻 |
|---|---|
| `#list` | 설계 목록 |
| `#case=rv-band` | 그 화면 + 탭은 자동 |
| `#case=adv-2&tab=0` | adv-2를 보면서 까망이는 검토 탭을 펴 둔 상태 |

`&tab=`은 **기본값과 다를 때만** 붙는다 — 평소엔 `#case=…` 하나로 깔끔하게 남는다.
탭을 눌러도 화면은 안 바뀐다(까망이는 화면 선택기지 화면이 아니다).

고친 것 둘 — `#list`에서 `S.case`가 안 비워져 탭이 안 따라왔고,
주소가 집어 준 탭을 자동 추종이 덮고 있었다(`_mpLast`를 현재 케이스로 맞춰 해결).
