## 문구 — 세 단계 "왜 하는지"를 공식 사유로 교체

내가 쓰던 ①단 이득(`1-1, 1-2처럼 잘게 나뉜 문항도 경계가 확실해져요`)은 **폐기**.

| 단계 | 근거 원문 |
|---|---|
| ① 빈 활동지·문항 확정 | 문항 지시문을 미리 확정해 두면, 학생 제출물의 낙서·메모로 훼손된 지시문을 AI가 오독하는 것을 막는다 |
| ② 채점기준 연결 | 각 문항에 요구되는 채점기준만 적용해 평가한다 |
| ③ 모범답안·채점 가이드 | 선생님이 생각하는 "상" 수준을 AI가 파악해 추론이 불가능한 답안도 채점 / 채점 가이드로 채점 고려 사항을 반영 |

- ①은 두 안 중 **1안(낙서·메모 오독)** 채택 — 2안(*"답안에 더 집중"*)은 무엇이 좋아지는지가 흐리다.
  바꾸려면 `ADV_WHY[1]`·`ADV_GAIN[1]`·`ADV_LOAD.ws.why` 세 줄
- 업계어는 풀었다 — `훼손된 지시문 오독` → `낙서나 메모를 문제로 잘못 읽음`,
  `"상" 기준 수준` → `잘한 답안의 수준`, `추론 불가능한 답안` → `미루어 짐작하기 어려운 답안`
- **③단은 두 줄로 나눴다** — 모범답안과 채점 가이드는 서로 다른 이득이라 이어 붙이면 뒤엣것이 묻힌다.

# 2026-09-03 오후 — stale 처리 재점검

**다음 세션(fable)이 이어받을 자리.** 아래 "남은 것"부터 읽으면 된다.

## 원칙 — 두 축을 섞지 않는다

| | 무엇 | 어떻게 |
|---|---|---|
| **지워지는 것** | 채점 결과 · 과제물 인식 결과 | 막지 않고, **저장할 때 모아서 한 번** 묻는다 |
| **낡는 것** | 문항–채점기준 연결 · 모범답안 | **표시만** 한다. 막지 않고, 저장 확인창도 못 잡는다 |

후자가 핵심이다. 저장 확인창은 *사라지는 것*만 잡으므로 **낡음은 화면에 신호를 남겨야 한다** — 줄리 우려(채점기준 바뀌면 ②연결도 다시 봐야 함)가 여기 걸린다.
공통 원칙은 [[feedback_optional_feature_minimal]] — 막지 않는다 / 상시로 알리지 않는다 / 저장할 때 한 번만 묻는다.

## 낡음 신호를 눈에 띄게

회색 배지 + `(다시 확인 필요)` 괄호로는 **고치고 나서 모르고 지나간다**(올립).

- **고도화 카드 행이 3상태** — `true` 초록 / `'redo'` 주황 / `false` 회색. 두 가지로 접으면 *"했는데 확인 필요"* 가 *"안 함"* 으로 읽힌다
- **카드 자체가 먼저 말한다** — `.adv-stale-on` 주황 테두리 + 연한 배경, 버튼 레이블도 `다시 확인하기`
- **`다시 확인` 칩 + 이유 한 줄** — 칩만 있으면 왜 다시 보라는지 모른다

## ②단 낡음 배너를 탭 바로 아래로

단 안에 두었더니 **세 번째 메시지라 묻혔다**(올립). 탭 바로 아래, **파란 "왜 하는지"보다 위**로 올리고 파란 배너와 같은 크기(16px/700)에 색만 주황.

**문구는 네 번 뒤집혔다.** 마지막 판정:

> **다시 연결하면 문항마다 바뀐 채점기준으로 채점해서 결과가 더 정확해져요.**
> 지금 연결은 채점기준을 고치기 전 상태예요. 이대로 채점해도 되고요. `AI가 다시 연결`

- `다시 연결해야 …` → `다시 연결하면 … 더 정확해져요` — **안 해도 새 채점기준으로 채점은 된다.** 막을 일이 아니면 막는 말투를 쓰지 않는다(26-09-03 올립)
- 직접 고치기와 재연결을 동등하게 뒀더니 *"그럼 채점기준 새로 만든 건 안 나오게 되잖아"* — **재연결 우선**으로

**동선**: ②단에 들어오면 팝업으로 **한 번만** 묻고(`S.staleAsked`), 닫아도 배너의 `AI가 다시 연결`로 언제든 다시 할 수 있다. `false → true` 전이일 때만 물음을 다시 연다 — 타이핑할 때마다 물으면 괴롭다.

| 상시 안내(꺼짐) | ②단 배너와 같은 말로 맞춤 |

행동 동사는 버튼과 같은 말 — 배너 `다시 연결` ↔ "다시 연결해 주세요", 검토 `다시 검토` ↔ "다시 검토해 보세요". 오전에 `다시 연결해야`를 뺐던 건 '해야'(강제) 때문이지 부탁형까지 막은 건 아니다 — ③단에서 올립이 직접 `새로 입력해 주세요`를 제안.

- ③단 배너 둘째 문장 정정(올립) — `전에 적어 둔 내용은 그대로 남아 있으니 …`는 **거짓**. 실제 시스템은 문항이 바뀌면 모범답안이 리셋된다. → `적어 두면 AI가 선생님이 생각하시는 잘한 답안의 수준에 맞춰 채점해요.`(②단과 같은 행동→이득 꼴).
  ⚠ 열린 질문: 목업은 문항 글자를 고쳐도 답안을 지우지 않는다(`markQuestionsChanged`는 표식만). 실제가 리셋이면 (a) 목업도 문항 편집 시 답안을 비우고 ③단 낡음 = '비어 있음'으로, (b) 아니면 '지워지는 것' 축이라 저장 확인창에 모범답안 줄이 들어가야 한다. 어느 쪽인지 올립 확인 필요.

## 문항 바뀜 = 낡음이 아니라 리셋 (올립 확정, A안)
**"전에 적어 둔 내용은 그대로 남아 있으니…"가 거짓이었다** — 실제 시스템은 옛 문항과 새 문항이 무엇끼리 같은지 맞출 수 없어 모범답안을 리셋한다. 같은 논리가 연결에도 적용된다.

| | 채점기준 바뀜 | 문항 바뀜 |
|---|---|---|
| 뒤 단계에 생기는 일 | **낡음** — 연결은 남고 다시 보면 됨 | **지워짐** — 연결·모범답안 새로 시작 |
| 신호 | ②단 주황 배너 + 카드 `다시 확인하기` + 팝업 1회 | 없음. ①을 떠나는 순간(`다음`·`저장`·`설계로 돌아가기`) **확인창 1회** `바뀐 문항으로 갈까요?` |
| 이후 | `다시 연결` 누르면 해제 | ②③은 '아직'(0건)으로 — 기존 `이어서 하기`가 받는다. ②는 들어가면 AI가 새로 연결 |

- `S.staleAnswer` 삭제 → `S.qEdited`(고쳤으나 확정 전). ③단 낡음 배너·카드 `다시 확인` 칩(③)·칩 점(③) 모두 제거 — 없는 상태를 남기지 않는다([[feedback_case_design_minimal]] 0건 흡수)
- `commitQuestions(then, saving)` — ①에서 나가는 세 길이 다 거친다. 저장이면 인식·채점 결과 줄까지 **한 창**에(창 두 번 금지). 지울 게 없으면 안 묻는다
- `resetDerived()` — links·answer·guide 비움, linkReady=false라 ② 진입 시 AI가 새로 연결
- 팝업 문구 정정(올립): `다시 연결한 뒤 필요한 곳만 손보시면 돼요. 직접 고치신 연결은 새로 만들어져요.`는 일부가 남는 것처럼 들림 → `지금 연결은 직접 고치신 것까지 모두 지우고, AI가 처음부터 다시 만들어요.`
- 케이스: `st-answer` = ① 문항 고치고 `다음`(확인창 두 줄) / `st-chain` = 채점 후 ① 문항 고치고 `저장`(연결·모범답안 + 인식·채점 결과 네 줄, 한 창)
- 실측: 두 케이스 확인창 문구·버튼(`지우고 계속`/`지우고 저장`), OK 뒤 links·answers 0 + ② AI 연결 시작, 나가기에서도 묻기, 지울 게 없으면 안 묻기. 콘솔 오류 0

## 채점된 학생이 있는데 채점기준을 통째로 바꾼 경우 (올립: "체크해보자")
- 구멍: 새 채점기준은 어느 문항에도 안 붙어 있는데(지운 기준의 연결은 그 자리에서 끊김) 저장하면 목록으로 나가 버려, 채점 결과를 지우고 다시 채점해도 새 기준이 빠진다. 통째로 갈면 연결은 '낡음'이 아니라 '없음'.
- 반영(둘 다 **이미 뜨는 저장 확인창** 안에서, 새 팝업 없음):
  1. 채점 인원을 실제 값으로 — `S.scoredN`(케이스: scored/st-score/st-both 28, st-chain 12). 1명이면 가볍게 지우고 28명이면 멈춰 생각하게.
  2. `relinkAfterSave()`(= 채점됨 + 채점기준 고침 + 연결 있음)이면 확인창에 한 줄 `저장하고 나면 문항 연결부터 새 채점기준에 맞게 다시 만들게요` + `지우고 저장` 뒤 목록 대신 **②단으로 가서 AI가 새로 연결**(`doSaveDesign(toRelink)`).
- 채점된 학생이 없으면 아무것도 안 뜬다 — 주황 안내를 무시한 건 선생님 선택, 다음에 고치면 그만.
- 접은 안: 확인창에 `복사본으로 저장` 세 번째 버튼. 채점기준을 통째로 바꾼 사람은 다시 채점하고 싶은 사람이라 `지우고 저장`이 정확한 행동이고, 옛 결과를 남기며 새 기준을 쓰는 건 목록의 '복사해서 만들기'로 시작할 일. 드문 경우로 버튼을 셋으로 늘리지 않는다.
- 올립: 플로우 체크는 기획서 어노테이션으로 직접 쓸 것. 목업은 **화면 예시**가 목적 — stale은 까망이 케이스로 팝업/안내가 보이면 충분, 실제 서비스 수준 동작 검증은 하지 않는다.

## 확인창 다시 (올립: "말이 이상한데")
- 제목은 **질문**으로 — `저장하면 지워지는 것이 있어요`(상태 보고) → `채점 결과를 초기화하고 수정 내용을 반영할까요?` / 인식이면 `과제물 인식 결과를 …` / 둘이면 `과제물 인식 결과와 채점 결과를 …`. 버튼 `초기화하고 반영`.
- 연결을 다시 만들라는 말은 지우는 얘기와 **섞지 않는다** — 파란 인포 한 줄(`.note-info`) `저장한 뒤 문항 연결을 새 채점기준에 맞게 다시 만들어 주세요.` 참고 안내로만. 저장 뒤 ②단 자동 이동은 뺐다(행동은 선생님 몫).
- `취소하면 고치신 내용은 그대로 남아 있어요` 삭제 — 확인창은 `되돌릴 수 없어요.`로 끝.

## 채점기준 수정 = 연결 '낡음'이 아니라 '끊김' (올립 정정, 26-09-03 저녁)
내 이해가 틀렸었다 — 채점기준을 고치면 새 기준은 채점에 그대로 적용되지만 **문항 연결(매핑)은 리셋되어 빈 값**으로 들어간다. 시스템은 수정의 정도(오타인지 뜻이 바뀐 건지)를 모르므로 수정했으면 끊긴 것으로 본다. 그래서 안내는 '더 정확해져요'가 아니라 **`연결을 다시 확인해 주세요`**.

| 끊김 | 안 끊김 |
|---|---|
| 채점기준 이름(채점요소) 글 바뀜 · 배점 조건 글 바뀜 · 채점기준 추가/삭제 | 배점 숫자 · 급간 개수 |

- `RUBRIC_SNAP` + `rubricMeaningChanged()`: 이름·조건 글·id 집합을 비교. `markRubricChanged`가 끊김이면 links 전부 비우고 `staleLink=true`, `linkReady=true`(자동으로 다시 돌리지 않음 — 확인은 선생님 몫, ②단에서 AI에게 맡기거나 직접).
- **②단 진입 팝업(`askRelink`) 삭제** — 끊긴 연결엔 덮어쓸 것이 없다. ②단 상단 배너 + `다시 연결` 버튼만.
- 문구: ②단 `채점기준이 바뀌어 문항 연결이 끊겼어요. 연결을 다시 확인해 주세요. 문항마다 직접 고르셔도 되고, AI에게 맡기셔도 돼요. 빈 채로 두면 그 문항은 채점기준 없이 채점돼요.` / 카드 행 `문항 연결이 끊겨 있어요 [다시 확인]` / 확인창 인포 줄 `채점기준이 바뀌어 문항 연결이 끊겼어요. 저장한 뒤 연결을 다시 확인해 주세요.` / 상단 배너에 `채점기준의 이름이나 배점 조건을 고치면 문항 연결도 끊겨 다시 확인해야 해요.`
- **`되돌릴 수 없어요.` 전부 삭제**(올립: "왜 있는 거지? 싶다") — 초기화·사라져요가 이미 말한다. 되돌림 창은 `지금까지 해 둔 아래 내용은 사라져요.`
- 케이스 st-link/st-link2는 연결이 빈 상태(전부 미연결)로.

- **끊김 조건 정정(올립)**: 배점 조건 글(세부 내용) 수정은 **안 끊김**. 끊김 = 채점기준 수량 변경 · 채점요소(이름) 수정뿐. `rubricMeaningChanged`는 id 집합 + 제목만 비교. (올립 용어 '채점요소' = 목업의 rubric title, placeholder "무엇을 평가하는 기준인지")
- 확인창 줄은 **왜 초기화하는지**까지: `채점 결과 N명분 — 바뀐 채점기준으로 다시 채점해야 해서 지금 점수는 초기화해요. 오타만 고치셨어도 바뀐 것으로 봐요.` / `과제물 인식 결과 28명분 — 문항이 바뀌어 답안을 새 문항대로 다시 나눠야 해서 초기화해요.` '근거가 달라져요'로 끝나면 왜 지우는지 안 읽힌다(올립). 오타만 고쳐도 뜨는 창이라 그 경우를 문구가 덮는다.
- 하늘색 인포 줄은 연결이 실제로 끊겼을 때(`staleLink`)만 — 배점·조건 글만 고친 저장에는 안 뜬다.
- `오타만 고치셨어도 바뀐 것으로 봐요.` 삭제(올립: 긁어 부스럼) — 앞 문장이 이유를 다 말하고, 묻지 않은 질문에 먼저 답하는 꼴. 오타만 고친 사람은 창을 보고 취소하면 된다.
- 확인창 줄 최종(올립: '연결 안 돼'): `<무엇> — <왜>`로만. `채점 결과 N명분 — 채점기준이 바뀌어 다시 채점해야 해요` / `과제물 인식 결과 28명분 — 문항이 바뀌어 답안을 다시 나눠야 해요` / 연쇄 `답안이 다시 나뉘어 다시 채점해야 해요`. '초기화'는 제목이 이미 말하니 줄에서 반복하지 않는다. 목록 줄이라 마침표 없음.
- 확인창 본문을 **문장 두 개**로(올립 제안): `채점기준이 바뀌어 다시 채점해야 해요. 저장해 둔 **28명의 채점 결과**는 초기화돼요.` / `문항이 바뀌어 답안을 다시 나눠야 해요. 저장해 둔 **28명의 과제물 인식 결과**는 초기화돼요.` 연쇄면 둘째 문단이 `…채점 결과도 초기화돼요`. 라벨(`무엇 — 왜`) 꼴 폐기. 합니다체(`초기화 됩니다`)는 해요체로 통일.
- 문항 확정 창(`바뀐 문항으로 다시 시작할까요?`)도 같은 꼴로(올립: 보기 어렵다) — 설명문·목록 걷어내고 문장 하나에 '왜 → 무엇이 초기화' 하나씩: `문항이 바뀌어 옛 문항에 맞춰 둔 **문항마다 연결한 채점기준과 모범답안**은 초기화돼요.` + (저장이면) 인식·채점 문단 + `채점기준 자체는 그대로예요.` 버튼 `초기화하고 계속`/`초기화하고 저장`.
- `st-both` 정정 — 문항을 확정할 때 연결·모범답안은 이미 초기화되므로 그 뒤 채점기준을 고쳐도 끊길 연결이 없다. 케이스에서 `staleLink`·연결·답안을 빼고 라벨을 `채점 후 문항도 채점기준도 고침`으로. 인식 dirty와 연결 끊김은 동시에 성립하지 않는다(문항 변경이 연결을 먼저 지움).

## 초기화 확인창 통째로 정리 (올립: "한눈에 안 들어온다, 굳이 필요할까 — 다시 생각해서 정리하자")
안 읽힌 이유: 창마다 '왜'를 문장으로 되풀이. 이유는 상단 배너가 고치기 전에 이미 말했으니 창은 **원인 한 줄 + 초기화되는 것 명사 목록**만.

| 자리 | 제목 | 한 줄 | 목록 | 버튼 |
|---|---|---|---|---|
| ① 문항 확정(다음·저장·나가기) | 문항이 바뀌었어요 | 바뀐 문항에 맞춰 아래를 초기화하고 다시 해요. | 문항 연결 · 모범답안 · 과제물 인식 결과 28명 · 채점 결과 N명 (있는 것만) | 초기화하고 계속 / 초기화하고 저장 |
