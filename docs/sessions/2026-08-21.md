간편/정교 2종 구분을 없애고 **평가 1종**으로 통합했고, 설계 상세에 **AI 채점 적합성 진단**(빈 활동지 → 문항 구조 → 채점기준 연결 → 적합도 진단)을 새로 붙였다.

## 화면 구성 (v5)

| 화면 | 해시 | 내용 |
|---|---|---|
| 설계 목록 | `#list` | 카드 6장. **정교/간편 뱃지·4점 진행 도트 제거** → `작성 중`/`확인 필요`/`설계 완료` + 요약 한 줄 |
| 설계 상세 | `#case=new` 등 | 세로 스크롤 + **좌측 sticky 목차**(7항목·완료 점·진행률). 진단·모범답안은 **요약 카드만** |
| 적합성 진단 | `#case=upload`→`structure`→`linking`→`result` | **4단계 스텝 플로우** (아래) |
| 모범답안 입력 | `#case=answer` | 문항별 textarea + AI 초안. 진단 4단계 완료 후에만 열림 |

### 설계 상세 섹션 순서
기본 정보 → 성취기준 → 채점기준 → AI 채점 적합성 진단 → 모범답안(선택) → 점수 계산 방식 → 결시자 처리

### 진단 4단계
1. **빈 활동지 업로드** — 드롭존 → 파일 카드 → `문항 구조 분석`
2. **문항 구조 확인** — v4 2단계 원본 이식(번호 input·↑↓ 이동·삭제·∑ 수식). 구분 실패 케이스 포함
3. **채점기준 연결** — v4 3단계 원본 이식(좌 문항 목록+연결완료/미연결 뱃지 / 우 AI 선택 이유 + 체크박스 + 모두 선택·해제)
4. **적합도 진단(신규)** — ① 총평 태그 `양호`/`보통`/`보완 필요` ② 보완사항 의견 ③ **재구성한 루브릭**(기존 채점기준 입력 UI 그대로, 편집 후 적용 가능)

상단에 진행 바. 완료한 단계는 클릭해 되돌아갈 수 있고, 전진은 "저장 후 다음으로"로만.

## 정책 결정

### 1. 진단은 팝업 아님 · 전용 화면
읽고·비교하고·결정하는 긴 과업이라 모달은 부적합(인라인>팝업). 상세가 길어지는 문제는 **전용 화면 2개(진단·모범답안)로 분리**해서 해결. 상세엔 상태별 요약 카드만 남긴다.

### 2. 진단은 순차 진입 — 업로드를 별도 버튼으로 빼지 않음
상세의 진단 버튼 하나가 4단계 플로우의 진입점. **4단계까지 마쳐야 모범답안이 열린다**(`S.diagDone`).

### 3. 재진단 트리거 (참조 원칙 적용)
| 변경 | 문항 연결 | 진단 판정 |
|---|---|---|
| AI 재구성안 적용 | 유지 | 확정(`적용됨`) — **재진단 불필요**. AI가 만든 문장이라 적합성이 보장 |
| 사람이 수정·추가 | 유지 | 무효 → `확인 필요` 표식 + `다시 진단` 유도 |
| 채점기준 삭제 | 소멸 | 무효 |
| 다시 진단 | **교사가 바꾼 연결 안 덮음** | 활동지 재업로드 없이 4단계만 재실행 |

### 4. 재구성안은 개별 적용 없음 · 일괄 + 덮어쓰기 안내
카드마다 버튼을 두면 요소가 많을 때 여러 번 눌러야 함 → 상단 `재구성안 N건 적용` 하나로.
"추가 vs 덮어쓰기" 옵션은 **주지 않는다** — 재구성안은 기존 기준을 고쳐 쓴 버전이라 추가하면 중복 채점 + 만점 합계 뒤틀림. 확인 다이얼로그에서 "덮어쓰며 문항 연결은 유지"를 안내하는 것으로 갈음. 원본 보존이 필요하면 설계 복제가 그 역할.

### 5. 총평은 재구성안 적용에 따라 실시간 갱신
남은 보완 건수 0=양호 / 1=보통 / 2+=보완 필요. **신뢰도·적합도 % 표시 안 함**([[feedback_system_honest_signaling]]).

### 6. 채점기준 추가 = 개발 화면 준수
Figma `MM23uA7pDEmFeMKGeFVJpB` `736:9578`(평가계획 생성) 기준으로 교체:
- 헤더의 "채점기준 추가" 버튼 제거 → 목록 아래 **점선 카드**(bg `#F7F4FF` / 2px dashed `#BDA4F6` / radius 8 / padding 32px 20px)
  - `채점기준 AI 생성`(bg `#8751FA`, h32, px12, 아이콘 16px, 14px bold white) / `또는` / `직접 추가`(white, 1px `#BDA4F6`, text `#6C2DF4`)
- 카드 헤더 ghost 버튼 h32·px4·gap6·14px bold `#494949`, 라벨 **복제**(copy-plus) / 삭제
- **배점 추가 / 배점 삭제**(h36), 세부 기준 칸마다 **∑ 버튼**(24px, `#F2EDFF`/`#BDA4F6`, radius 6)
- 좌측 채점요소 textarea **198×132, radius 6**, 배점 칸 58px
- 하단 `어떻게 입력해야 하나요?  채점기준 입력 예시`(16px bold `#333` + `#6C2DF4`)
- 신규 설계는 **채점기준 0개 + 점선 카드**로 시작

> 이 섹션만 Figma 실측값(`#8751FA`/`#6C2DF4`)을 쓴다. 나머지 화면의 `#7E44FB`는 그대로 뒀다(전역 토큰 교체는 범위 밖).

## 배운 것

- **기존 화면이 있는 단계는 재창작하지 말 것.** 2·3단계를 "진단 결과 리포트" 프레임으로 새로 그렸다가 v4 원본으로 되돌렸다. 번호도 교정 대상이라는 점(고정 "1번"으로 그렸었음), AI 선택 이유 노출, 인라인 체크박스 — 원본이 담고 있던 판단이 재창작으로 전부 소실됐다. 같은 지적을 채점기준 추가 버튼에서도 받음 → 메모리 `feedback_reuse_existing_screens_first` 등록.
- **sticky는 부모가 `align-items:flex-start`면 안 먹는다.** aside 높이가 콘텐츠만큼만 잡혀 이동 구간이 없음 → `align-items:stretch`.
- JS 문자열 안에 `onclick="showToast('info', …)"`를 넣으면 따옴표가 겹쳐 파싱이 깨진다 → 이름 붙인 핸들러(`openFormulaTip()`)로 뺄 것.
