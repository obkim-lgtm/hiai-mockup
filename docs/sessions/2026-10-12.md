노션 H-2608 페이지 맨 위에 v2.1 작성, v1.4는 올립이 `## 이전 문서` 토글로 이동. 상세 규칙은 [../precise-design.md](../precise-design.md).

### 한 것
- v1.4(올립) ↔ v2.0(줄리) 차이 정리 → 충돌 3건 결정(OCR 관계: 맥 10-07 확인 복원 / 기본 설계 수정 정책: 기개발이라 QA 참고 섹션으로 수록 / 띠·확인창: 디자인 소관).
- 간소화: 확인 9종→6종(C1~C6), `!` 해소 = 저장 1가지, ①②③ 저장본 정의, 1단계 저장 조건, C2 트리거, 진입점 2곳, n/4 서브텍스트 삭제, 2단계 경고 상시.
- 올립 지적으로 디자인 사양(크기·색·형태·위치·문구 전문·확인 UI 유형) 전부 제거 → §3 "화면별 동작"으로 개편. 원칙 #20 등록.
- 채점기준 AI 검토는 §7 백로그 1행.

### 줄리 관점 2차 검수
- 질문이 나올 틈 11곳을 문장으로 닫음: 잠금 조건=① 비어 있음, 요약 패널 전환 조건 동일 기준, 빈 문항 정의(지시문 기준·번호 자유), 활동지 파일 보관은 저장과 무관, 인식 0개=실패, 2단계 선택 화면은 연결 이력 없을 때만(재진입 즉시 연결 화면·초기화 뒤 재표시), 3단계 열림 상태 비저장, `!` 표시 시점(만든 저장 직후부터·그다음 정교한 설계 저장에서 해소), 복사본 `!`도 동일·초안 미복사, [나중에 할게요] 동작, QA 2단계 재진입 행.

### 줄리 추가 댓글 2건(오후 늦게)
- C6 '잃는 것'에 학생 답안 삭제 보충 요청 → PRD C6·C5에 반영, 확인 문구는 피그마 소관으로 답글.
- '문항 추가·삭제 시 OCR 재실행' 제안 → 올립이 불채택 답글(비용·교사 수정분 덮어씀·빈도 낮음). 후속 배포 항목으로만 유지.
- §3.4 "다시 연결 실패 시 기존 연결 유지"(올립 추가)에 줄리가 @빌 확인 요청. 원인: C4 셀이 "기존 연결을 모두 지우고 다시 연결" + "실패 시 유지"를 같이 적어 모순. 올립 결정 '유지'로 C4 셀 수정(성공 시만 교체, 실패·중단 시 그대로). C7·QA는 이미 유지 기준. 줄리 스레드에 올립 톤으로 빌 질문 + "어려우면 개발 의견 따름" 답글. 올립이 슬랙용 초안을 같은 스레드에 직접 게시.
- 줄리가 §3.3 1단계 같은 문장("다시 인식 실패 시 기존 문항 유지")에도 @빌 확인 요청. get-comments가 댓글 1개짜리 스레드를 목록에서 잘라 내가 "새 댓글 없음"으로 잘못 보고 → 페이지 fetch의 discussion 마커로 발견. §3.4 스레드로 모아 답글. 같은 문장에 남아 있던 "되돌리기가 모달 닫은 뒤 가능한지 개발 확인 필요"는 '마지막 저장본 복원, 다음 저장 전까지 가능'으로 확정해 미정 제거.

### 노션 편집 메모
- update_content는 토글·번호 목록 안의 줄을 잘 못 찾는다. 표 셀·불릿 단위의 짧은 old_str이 안전. 긴 블록 교체는 섹션 단위 old_str로 한 번에.
- 사용자가 동시에 편집 중이면 대조 문자열이 어긋난다 → 재조회 후 diff로 확인하고 다시 보낼 것.
- get-comments(include_all_blocks)는 댓글 수 많은 순으로 16~17개만 보여 준다(총 33개 중). 새 댓글 확인은 fetch(include_discussions)의 discussion 마커 집합을 이전과 비교하고, 처음 보는 ID는 discussion_id로 개별 조회할 것.

### 활동지 변경 되돌리기 철회(저녁, 슬랙 빌 답변)
- 줄리가 슬랙에서 빌에게 "재업로드 후 추출 실패 시 이전 활동지로 되돌리기 가능?"을 물음. 빌: 재업로드 = 삭제 후 업로드, 문항은 활동지에 딸려 함께 삭제. 되돌리기는 플로우를 '추가 업로드 후 별도 삭제'로 바꿔야 가능.
- 올립 결정: 현재 개발 구조 따름(일정). PRD §3.3 인식 문장·§3.2 저장 규칙 예외·C5·C7·QA 1행에서 되돌리기 삭제, "활동지 변경 = 즉시 삭제, 되돌릴 수 없음" 명시. 내가 몇 시간 전 확정한 "되돌리기 = 저장본 복원"은 철회.
