# 목업 내비게이터(까망이) 규칙

시연용 다크 플로팅 패널. 제품 UI가 아니라 **목업을 보여주기 위한 도구**다.
새 목업을 만들 때나 기존 목업에 케이스를 추가할 때 이 규칙을 따른다.

구현체: `#mockpick` (output/*.html 하단 "까망이 목업 내비게이터" 블록,
`mp-head` / `mp-cap`(그룹) / `mp-btn` + `mp-sub`(부제) / `mpGo()` 화면 전환).
CLIPO 목업도 같은 규칙을 쓴다(구현체 이름만 `#mockNav`) — 두 서비스 공통 지침.

## 1. 목업 도구는 하나, 어느 화면에서도 나갈 수 있어야 한다

- **어떤 화면에서도 까망이를 숨기지 않는다.** 특정 화면에서만 뜨는 전용 패널을
  따로 만들지 않는다.
- 화면별 케이스 선택기가 필요하면 전용 패널이 아니라 **까망이 안의 그룹**으로 넣는다.

> 왜: CLIPO에서 한 상세 화면만 전용 케이스 패널을 띄우고 까망이를 숨겨, 그 화면에
> 들어가면 다른 화면으로 나갈 길이 사라졌다. 같은 성격의 상세인데 화면마다 도구가
> 달라 보이는 문제도 함께 생겼다(2026-07-29 정리).

## 2. 진입 항목 → 그 화면에서 케이스 그룹으로 펼친다

| 위치 | 까망이에 보이는 것 |
|---|---|
| 목록·상위 화면 | 상세로 가는 **진입 항목 1개** |
| 그 상세 화면 | **같은 이름의 그룹**이 케이스 목록으로 펼쳐짐 (정상 + 실패·변형 케이스) |

- 케이스 그룹이 펼쳐진 화면에서는 **진입 항목을 숨긴다** — 같은 라벨이 두 번 보이지 않게.
- 케이스가 많아도 화면과 무관한 케이스를 늘 펼쳐두지 않는다. 지금 화면에서 볼 수
  있는 것만 보이게 한다.

## 3. 모든 케이스는 딥링크 + 활성 표시

- 케이스마다 고유 URL을 준다(`?param` 점프). 새로고침·링크 공유로 같은 화면이
  복원돼야 한다. 파일이 나뉘어 있으면 파일 간 점프도 같은 파라미터 규칙으로.
- **지금 보고 있는 케이스가 활성 표시**돼야 한다. 화면 상태가 바뀌면(케이스 전환·
  모달 오픈) 활성 표시도 같이 갱신한다.
- 화면 자체의 해시 라우팅은 principles.md 12번(화면·탭·스텝마다 고유 URL)을 따른다.

## 4. 라벨·표시

- 그룹 안 라벨은 **평행하게**(정상 → 실패 케이스 순, 어미·형태 통일).
- 부제는 `mp-sub` — 작은 보조색, 줄바꿈 허용. **가로 스크롤 금지.**
- **버전·신규 표시를 넣지 않는다**(예: `v2 신규 · 모달`). 목업 이력이지 리뷰어에게
  필요한 정보가 아니다. 부제는 케이스 성격 설명에만 쓴다. (2026-08-06)
- **실제로 쓰지 않는 도구 버튼은 넣지 않는다**(예: 케이스 리셋).
- 실제 동작하지 않는 항목(빈 핸들러)은 만들지 않는다 — principles.md 10번.

## 4-1. 모달을 여는 케이스도 `mpGo()` 안으로 (2026-08-06)

까망이 버튼에 `onclick="openXxxModal()"`을 **직접 물리지 않는다.** 한꺼번에 세 가지가 깨진다.

- **`mpGo()` 첫머리의 "열려있는 모달 닫기" 목록에 신규 모달을 반드시 추가한다.**
  빠뜨리면 모달을 띄운 채 다른 케이스를 눌러도 **모달이 그대로 덮여 있어** 화면이
  바뀐 걸 못 본다. 까망이 z-index가 오버레이보다 높아 클릭은 되므로 더 헷갈린다.
- 그 상태에서 같은 모달 버튼을 다시 누르면 이미 열려 있어 아무 변화가 없고,
  **"버튼이 안 눌린다"로 보고된다.** 원인은 버튼이 아니라 위 항목이다.
- 케이스로 편입하면 `data-k` 활성 표시·딥링크·재오픈이 함께 따라온다.
  화면 전환 없이 모달만 여는 케이스는 `openXxx()` 후 `history.replaceState`로
  자기 URL(`#case=<키>`)을 유지한다 — `showScreen()`이 URL을 덮어쓰기 때문.
- 실제 사례: `task_ocr_review_v2`(준비 팁 모달) · `evaluation_design_v4`.

## 5. 여러 파일에 나뉘어 있으면 동기화한다

- 같은 까망이가 여러 파일에 삽입돼 있으면 라벨·그룹·케이스를 **모든 파일에서 동일**하게
  유지한다. 한 파일만 고치면 화면을 옮길 때 도구가 달라 보인다.
- 삽입 파일 확인: `grep -l mockpick output/*.html`

## 6. 기본 사양 (건드리지 말 것)

- 다크 플로팅 · 드래그 이동 · 헤더 클릭으로 접기(알약) · 위치·접힘 상태 유지.
- 헤더에 `MOCKUP · <화면 컨텍스트>` 표기.
- 제품 UI가 아니므로 시연·캡처 외 기능은 넣지 않는다.
